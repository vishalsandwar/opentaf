## 1. Purpose

This document defines the OpenTAF maturity model for organisations progressing from traditional digital transformation toward governed Agentic AI-enabled operations.

The model provides a structured way to assess:

* Digital maturity
* Process maturity
* Enterprise architecture maturity
* AI adoption
* Agentic capability
* Governance
* Operating model readiness
* Human oversight
* Enterprise integration

The model is intended to help organisations determine **where they are today, what capabilities are required next, and how AI autonomy should evolve responsibly.**

---

# 2. OpenTAF Maturity Model

OpenTAF defines six maturity stages:

```text
L0
DIGITAL
   ↓
L1
INTELLIGENT
   ↓
L2
AGENT-ASSISTED
   ↓
L3
AGENT-ORCHESTRATED
   ↓
L4
GOVERNED AUTONOMOUS
   ↓
L5
ADAPTIVE ENTERPRISE
```

The progression is not simply about increasing AI capability.

Each stage requires corresponding improvements in:

**Architecture + Data + Governance + Operating Model + Human Oversight**

---

# 3. Level 0 — Digital Foundation

## Characteristics

The organisation has established core digital platforms but primarily relies on human-driven processes.

Typical characteristics:

* Core applications
* Digital channels
* Enterprise databases
* APIs
* Workflow systems
* Reporting
* Basic automation
* Manual decision-making

```text
Customer
   ↓
Digital Channel
   ↓
Application
   ↓
Workflow
   ↓
Human Decision
   ↓
Enterprise System
```

## Primary Focus

Build the digital foundation required for future intelligence.

### Required Capabilities

* Application architecture
* Data architecture
* Integration architecture
* Security architecture
* Cloud/platform foundation
* API capabilities
* Process standardisation

---

# 4. Level 1 — Intelligent Enterprise

The organisation begins using AI and analytics to improve decision-making and operational efficiency.

## Characteristics

* Business intelligence
* Predictive analytics
* Machine learning
* AI-assisted insights
* Recommendation engines
* Intelligent search
* Process analytics

```text
Enterprise Data
      ↓
Analytics / AI
      ↓
Insight
      ↓
Human Decision
```

AI primarily provides **information and recommendations**.

Human decision-making remains dominant.

---

# 5. Level 2 — Agent-Assisted Enterprise

AI evolves from providing insights to actively assisting people with defined tasks.

## Characteristics

* AI agents
* Document processing
* Knowledge retrieval
* Task assistance
* Workflow assistance
* AI copilots
* Context-aware recommendations
* Controlled tool usage

```text
Human
  │
  ▼
Agent
  │
  ├── Retrieve
  ├── Analyse
  ├── Recommend
  └── Prepare Action
  │
  ▼
Human Decision
```

The human remains the primary decision authority.

---

# 6. Level 3 — Agent-Orchestrated Enterprise

Multiple specialised agents begin collaborating across business processes.

## Characteristics

* Multi-agent architecture
* Agent orchestration
* Shared enterprise context
* Governed tools
* Automated workflow execution
* Human escalation
* Cross-system integration
* Policy-based control

Example:

```text
Customer Request
       ↓
AI Orchestrator
       ↓
 ┌─────┼─────┐
 ▼     ▼     ▼
Data  Risk  Process
Agent Agent Agent
 └─────┼─────┘
       ▼
Compliance Agent
       ↓
Human Approval
       ↓
Enterprise Action
```

The organisation begins moving from **AI assistance to AI-coordinated execution**.

---

# 7. Level 4 — Governed Autonomous Enterprise

Agents execute defined processes within explicit enterprise boundaries.

## Characteristics

* Bounded autonomy
* Policy-driven execution
* Automated decisions within defined thresholds
* Continuous monitoring
* Automated exception handling
* Human escalation
* Strong identity and permissions
* End-to-end auditability

```text
Business Event
      ↓
Agent Detection
      ↓
Planning
      ↓
Policy Check
      ↓
Controlled Execution
      ↓
Outcome Validation
      ↓
Exception?
   │       │
  No      Yes
   │       │
   ▼       ▼
Complete  Human
          Escalation
```

Autonomy is **bounded by policy, permissions and business rules**.

---

# 8. Level 5 — Adaptive Enterprise

The organisation operates an integrated environment where AI continuously supports transformation, operations and optimisation.

The focus shifts from individual AI use cases toward an **AI-enabled enterprise operating model**.

## Characteristics

* Multi-agent ecosystems
* Continuous optimisation
* Dynamic process orchestration
* Adaptive workflows
* AI-supported enterprise architecture
* Continuous risk monitoring
* AI-assisted transformation management
* Human strategic oversight

```text
                ENTERPRISE
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    Business     Technology     Data
        │           │           │
        └───────────┼───────────┘
                    ▼
             Agent Ecosystem
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
     Process       Risk       Architecture
      Agents      Agents        Agents
        │           │           │
        └───────────┼───────────┘
                    ▼
             Human Leadership
```

The objective is not unrestricted autonomy.

The objective is **adaptive enterprise capability within defined governance boundaries**.

# 11. Maturity Assessment

Organisations can assess each capability dimension on a scale from 0 to 5.

```text
0 ─────── 1 ─────── 2 ─────── 3 ─────── 4 ─────── 5
None    Digital  Intelligent  Agentic  Autonomous  Adaptive
```

The overall maturity should not simply be calculated as an average.

A critical capability gap can constrain the achievable maturity level.

For example:

```text
Agent Capability       → L4
Data Governance        → L2
Security               → L3
Human Oversight        → L2
Enterprise Integration → L3
```

The organisation should not claim L4 operational maturity simply because the AI capability itself has reached L4.

---

# 12. Maturity Gate

OpenTAF introduces the concept of a **Maturity Gate**.

An organisation should satisfy minimum capability requirements before moving to a higher autonomy level.

Example:

```text
                  L4 Autonomous
                       ▲
                       │
              Governance Gate
                       │
              Security Gate
                       │
                 Data Gate
                       │
              Architecture Gate
                       │
              Operating Model Gate
                       │
                  L3 Agentic
```

This prevents organisations from increasing AI autonomy without establishing the supporting enterprise capabilities.

---

# 13. Autonomy vs Maturity

OpenTAF separates:

**Enterprise maturity**

from

**Agent autonomy**.

A mature organisation may deliberately operate many agents at lower autonomy levels.

Conversely, an organisation should not increase autonomy merely because the technology permits it.

```text
Enterprise Maturity
        │
        │
        │      Appropriate
        │      Autonomy Zone
        │          █████
        │        ███████
        │      █████████
        │
        └─────────────────────
                 Agent Autonomy
```

The appropriate autonomy level depends on the business context and risk profile.

# 15. Example — Customer Onboarding

The same business process can evolve through the maturity model.

### L0 — Digital

Customer submits information digitally.

Humans perform most validation.

### L1 — Intelligent

AI identifies missing documents and provides risk insights.

### L2 — Agent-Assisted

Document Agent extracts information and prepares the case for an employee.

### L3 — Agent-Orchestrated

Document, KYC, Risk and Compliance Agents collaborate to prepare the onboarding decision.

### L4 — Governed Autonomous

Low-risk cases can proceed automatically within predefined policies.

Exceptions are escalated to humans.

### L5 — Adaptive

The enterprise continuously analyses onboarding performance and agents dynamically support process optimisation within approved governance boundaries.

# 21. OpenTAF Maturity Model Principle

OpenTAF follows a simple principle:

> **Increase enterprise capability before increasing autonomous capability.**

The maturity journey therefore focuses on building the architecture, data, governance and operating model required to support responsible Agentic AI adoption.
